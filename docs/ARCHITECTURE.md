# 课业看板 · 微信小程序

把**学习通**、**希冀平台（Educoder）**、**U校园** 三个平台里没做完的任务，聚合到一个按截止时间排序的清单里。

- 前端：微信原生小程序（无第三方框架）
- 后端：微信云开发 · 云函数 `studyHub` + 云数据库
- 抓取：Node 18 内置 `fetch` + 自研 Cookie 容器，零额外依赖
- 自动化：云函数定时触发器每天 21:30 自动同步，可推送微信订阅消息

> **第一次部署请看 [`手把手部署手册.md`](./手把手部署手册.md)**，那份是逐步照着做的；本文件只讲架构和注意事项。

## 三、跑起来（约 15 分钟）

### 1. 导入项目
微信开发者工具 → 导入项目 → 选 `study-hub` 目录 → 填入你的 **AppID**（个人主体即可）。
`project.config.json` 里当前是 `touristappid`，导入时工具会让你替换。

### 2. 开通云开发
**别在开发者工具里点「开通」**（那里建的是付费套餐）。去腾讯云控制台 <https://console.cloud.tencent.com/tcb> 创建**免费体验环境**（3000 点/月，自用足够），再把环境 ID 填回来。

注意：免费环境在**小程序正式发布后 15 天到期**。自己用别发布，走体验版就一直是免费的。详见手册第 4.1 节。

把 `miniprogram/app.js` 第 1 行改成你的环境 ID：

```js
const CLOUD_ENV = 'your-env-id-xxxxx'
```

### 3. 建五个数据库集合
云开发控制台 → 数据库 → 新建集合：`accounts`、`tasks`、`reminders`、`zzu_sessions`、`users`。

**所有集合的权限都选「仅管理端可读写」**（列表里的第四项）。
前端不直接碰数据库，所有读写都走云函数，云函数以管理员身份运行，不受此限制。这样即使别人拿到集合名也读不到任何人的数据。

> `users` 存的是「这个微信是谁」：本校学生（学号）还是访客（手机号 + 密码哈希）。第一次注册访客时云函数会自动建，手动建一下只是提前把权限设好更稳。**里面只有加盐 sha256，没有密码明文**，也不存手机号以外的个人信息。

> `zzu_sessions` 是课表导入用的：云端登录郑大统一认证（APP /token/ 通道）后，把约一个月免密的 idToken 加密存在这里；等短信验证码的几分钟里会临时存一份双保险加密的账号密码密文，验证完即清。第一次点「登录并导入课表」时云函数会自动建这个集合，手动建一下只是提前把权限设好更稳。

建议给 `tasks` 加索引：`openid`(升序) + `platform`(升序)，数据多了查询更快。

### 4. 部署云函数
右键 `cloudfunctions/studyHub` → **上传并部署：云端安装依赖**。

部署完在云开发控制台 → 云函数 → `studyHub` → 配置：
- **超时时间改成 60 秒**（默认 3 秒，抓三个平台必然超时）
- Node.js 版本：能选 18.x 就选；**选不了也不用管**，代码已兼容 Node 16.13（会自动降级到内置 http 模块）

### 5. 改掉默认密钥
`cloudfunctions/studyHub/lib/secret.js` 第一行的 `SECRET` 换成你自己的随机字符串，再重新部署一次。

> 改了 SECRET 之后，之前绑定的账号会解不开，需要重新绑定。所以**先改再绑定**。

## 四、三个平台的抓取现状（重要，请先读这段）

抓取逻辑基于各平台**网页端内部接口**，这类接口没有官方文档、会随改版变化。我把每个平台拆成了独立适配器，下面如实说明它们的成熟度：

| 平台 | 登录 | 课程列表 | 任务明细 | 说明 |
|---|---|---|---|---|
| 学习通 | 较稳（扫码 / Cookie / **本地代理**） | **已跑通**（7 门课实测） | **作业 + 考试已跑通** | 实测能抓到课程名、老师、作业标题、截止时间、状态。**云函数机房 IP 常被超星区别对待**，遇「请重新登录」就用 `localserver/` 本地代理，见下方「本地代理」。章节任务点（视频）按章汇总 |
| 希冀 Educoder | 公网版 Cookie；**内网版：学号 + 密码 + 验证码，小程序直连** | **已校准真实接口** | **内网版已打通（登录 + 表格页解析）** | 公网版走 Educoder 真实在用的路径：`/api/courses/mine.json` + `/api/courses/{id}/homework_commons.json`。内网版（`http://10.67.4.14` 这套 JSP）**登录已通**：密码先用页面同款 AES-128-ECB 加密再提交，会话 Cookie 自己存自己带；**作业靠课程页表格解析**——只收「一行里既有作业标题、又有截止时间」的行，没有日期的一律不猜。相对链接会按 `base href` / 页面目录 / 根目录 / `indexcs` 四种拼法挨个试（真机上就是一律拼 `/indexcs/` 才整排 404）。**学生首页是外壳页**（只有导航 + `form /main.jsp`）时会顺着 form / iframe / JS 里出现的 `.jsp` 往下摸，最多两层；真正的数据源是**服务端渲染的 tab 页**——`/includes/redirect.jsp?tab=-2`（在线作业）里一行一条 `index.jsp?courseID=124&assignID=802`，`assignID` 就是作业号，直接解析成任务（详情页是 JS 外壳，进去只有同一个页面，所以不进去）。**tab=-2 只列「当前课程」**——所以同步完还会补一轮：换栏目（`tab=-1/-3/-4`）、换课程（先试 `tab=-2&courseID=N`，不灵就打开切换页让服务端记住课程，哪种写法灵就锁定复用）、翻页（`下一页` / `pageNo=`）；课程清单从课程链接、作业行的 `courseID`、课程下拉框的 `<option>` 三处凑，有 15 秒硬上限，宁可先交一部分也不卡死。**注意两个入口别搞混**：账号页顶部的「希冀平台（公网头歌）」走云端访问 `www.educoder.net`，校内自建部署的账号不在那里、云函数也摸不到 `10.x` 地址，所以一定登不上；内网版只能用下方「希冀 · 校园内网直连」那张卡（本地保存了旧文案的云函数会回一句「登录未拿到会话 Cookie，可能触发了风控」，见到它换入口即可） |
| U校园 | 扫码 / Cookie / **密码（SSO JSON 接口）** | **已按 AI 版 5.0 重写** | **已按 AI 版 5.0 重写** | 老适配器猜的接口在 U校园里不存在——这就是「登录成功却拉不到任务」的原因。现在走 uai.unipus.cn 真实接口（用户信息 → 课程列表 → 单元策略 → 单元完成度），任务粒度是教学单元，见下方「U校园（AI 版 5.0）」 |

### U校园（AI 版 5.0）

2026-10 按真实接口重写了 `adapters/unipus.js`（路径来源：开源项目 UnipusHelperPro / AutoUnipus 的逆向核对）：

| 数据 | 接口 | 说明 |
|---|---|---|
| 登录态 + 用户 | `GET uai.unipus.cn/api/account/user/info` | 顺便拿 `appUserId` / `ssoId`，查进度要用 |
| 课程列表 | `GET uai.unipus.cn/api/cmgt/course/getCourseListByStudent` | 每个班挂的教材资源（instanceId / strategyId）都在这里 |
| 单元 + 学习截止 + 星号清单 | `POST uai.unipus.cn/api/tla/courseStudyStrategy/detail` | 每个单元的 `studyEndTime` 是交作业的线；**`requiredTask` 就是老师打了星号（必修）的任务清单** |
| 单元任务树 | `GET uai.unipus.cn/api/tla/learningDetail/studyRecord/unitTaskSituation` | 逐个星号单元拉任务树，叶子 `required=true` 的就是要显示的任务 |

两个关键点：

1. **Cookie 里必须有 sso.unipus.cn 的统一认证会话**（扫码登录就有）。`uai.unipus.cn` 自己没有会话，适配器会先 GET 一次 `uai.unipus.cn/home` 让 SSO 发一份；被留在登录页时明确报「统一认证登录态已失效，重新扫码」，不再含糊。
2. **密码登录有一条活路**：SSO 的 JSON 接口 `POST sso.unipus.cn/sso/0.1/sso/login` 收明文（老说法「密码走不通」指的是网页表单那套动态 RSA，API 不走那套）。适配器已接上；反复失败（触发滑块）就回扫码 / Cookie。

**只显示老师打了星号或给分的任务，并且带完整层级**：学生端带 ★ 的内容就是老师设置的必修任务；叶子上 `scoreTaskFlag=true` 的「其他类型」（作业/测验等老师记成绩的地方）也一并显示。任务归属按「班级·书名」分组（一门课挂读写、视听说多本教材时分开），标题是「单元 · 中间层级 · 具体部分」（如 `Unit 1 Language in mission · Section A > Quotation`），一眼看出哪本书哪个章节哪个部分；层级名连续重复会自动去重。老师没点星的单元整个隐藏；任务树解析不出来时保底显示单元本身；全程没星号会明确提示「老师没有标记星号任务」，不误报接口错误。学期仍按课程开始时间自动标注。

### 学习通抓的是哪些数据（2026-10 实测）

| 数据 | 状态 | 说明 |
|---|---|---|
| 课程列表 | ✅ | `backclazzdata` 接口，字段是 `d.id` / `content.id`（不是老版的 `courseid` / `clazzid`） |
| 作业标题 / 截止时间 / 状态（待做·待批阅·已完成） | ✅ | `/mooc-ans/work/getAllWork`，**必须带 `enc`** |
| 考试标题 / 考试时间区间 / 状态（未开始·已结束） | ✅ | `/exam-ans/exam/test`，同样要 `enc` |
| 章节任务点（视频 / 阅读） | ✅ 按章汇总 | 直接复用课程目录页里的 `knowledgeJobCount`（那一章**未完成**的任务点数），不多发请求；每门课最多取 12 章，避免大学物理这种一百多小节的课把首页冲掉 |

**`enc` 这一步最容易踩坑**：直接请求 `mycourse/studentcourse?courseId=..&clazzid=..` 会正常返回 200 和一个看着很像样的页面，但里面的课程内容一个字都没有——那是个机构通用模板。必须先走 `/visit/stucoursemiddle` 让它 302 到带 `enc` 的地址，再从页面里把 `enc` 和 `openc` 取出来。

**结论：三个平台都需要你用自己的账号第一次跑通并微调。** 这不是偷懒，是这类第三方抓取绕不开的现实——没有账号就没法验证接口返回。

### 首页长什么样（小组件磁贴）

首页走 iOS 那套视觉：系统色 + 半透明卡片 + 极轻阴影 + hairline 分割线。从上到下是四块：

1. **小标栏** —— 左边「郑好有你」，右边登录设置 / 主题 / 同步三个圆按钮（右侧留 200rpx 让开微信胶囊）
2. **结论标题** —— 不再用 104rpx 的裸数字，改成一句话：「还有 12 件事要交」，数字用系统蓝高亮；下面一行 `headSub` 回答「最急的是哪种」，取值为 `今天要交 N 件 · M 项已过期`，两档都说不出时退回「一周内还有 N 件」
3. **2×2 磁贴** —— 待完成（副标题写过期数）、完成率（右下角进度环）、专注、记事本。后两个可点，直接进对应页面
4. **平台胶囊 + 全量同步** —— 三格胶囊显示各平台未完成数，未绑定写「绑定」、登录失效整格描红；下面是蓝色实心「同步全部课程和任务」

再往下是筛选（学期 → 平台分段 → 课程）和任务流：卡片改成「平台圆点 + 平台名 + 课程名 + 右上角截止胶囊」，已过期的整卡泛红。

**几个实现上的坑**：

- **背景渐变不要单独放在一个 `position: fixed` 的整屏层里**（这是首页真正的空白元凶，比上面那条 `wx:elif` 更隐蔽，两次真机白屏都是它）。原来 `.page-bg` 是 `position: fixed` + `inset: 0` + `z-index: 0` 的一层不透明渐变：按层叠顺序，`z-index: 0` 的定位元素画在所有**未定位**的普通流元素之上，于是今天课程、分组标题、任务卡、「新任务」按钮全被盖住；而 `.head` 有 `z-index: 2`、`scroll-view` 自带 `position: relative`，磁贴和筛选胶囊反而浮在上面 —— 症状就是「上半屏一切正常，筛选行以下一片空白，控制台零报错」。**浏览器预览永远看不出这个问题**（预览根容器有定位，背景层就落在内容下面）。现在背景直接写在 `.page` 的 `background-image` 上，`.page.theme-dark` 给深色那套；内容块（`.today-card` / `.group-head` / `.task` / `.notice` / `.empty-guide` / `.remind`）统一 `position: relative; z-index: 1` 兜底。`test/layer.js` 会拦「fixed + z-index: 0 的整屏层」和「根容器没有背景」。
- **`wx:elif` / `wx:else` 前面绝对不能夹注释**。WXML 要求这两个指令紧跟同级节点，中间插一条 `<!-- -->`（哪怕隔了几行空白）整条链会**静默失效**，四个分支一个都不渲染。首页就栽在这：`skeleton` 的 `wx:if` 后面接了「未绑定引导」的注释再接 `wx:elif`，结果真机上「今日课程 + 任务列表」整块消失，只剩筛选胶囊和一大片空白，控制台一句错都不报。现在这段用的是三个互斥的独立 `wx:if`（`!loading && !hasAccount && isGuest` 这样写全），`test/wxml-chain.js` 会扫全项目的 wxml 防复发。注意：这条修完仍然空白的话，去看下一条（背景层遮挡），两者症状一模一样。
- **磁贴两列不要再写 `calc(50% - 7rpx)` + `flex-wrap`**。这行在部分基础库上会被当成非法值整条丢掉，四个磁贴就塌成一行一个（真机截图踩过：安卓上整屏被拉成一列竖卡）。现在的写法是两行 `<view class="tile-row">`，每行两个 `.tile { flex: 1 1 0 }`，不依赖 calc、也不依赖 `gap`。
- **进度环**用 `conic-gradient` 画，`style` 里直接拼 `{{stats.rate}}%`。`.ring` 自己留了一圈灰底兜底：个别安卓内核不认 `conic-gradient` 时是一条灰环，不会变成空白。
- **深色覆盖必须写 `.page.theme-dark`**（两个类）。`--tile-bg` 这类变量在 `.page` 里定义是单类权重，`.theme-dark` 单类压不住它，会变成「深色背景 + 白磁贴」。
- **深色配色单独一套**：`.page.theme-dark` 里把蓝/红/绿/橙/紫整组换成 iOS 深色系统色（`#0A84FF / #FF453A / #30D158 / #FF9F0A / #BF5AF2`），浅色那套 `#007AFF` 在近黑底上会发闷；磁贴底色 `#1B1D27`，靠 `1rpx` 白色 hairline 分层而不是靠投影（黑底上看不见投影）。结论数字在深色下单独提到 `#4DA3FF`。
- **下拉刷新的三个点**也要跟着主题换，`utils/theme.js` 里调了 `wx.setBackgroundTextStyle`，否则深色下是墨点掉进黑底。
- 预览用 `gen-index-css.py` 把 `index.wxss` 的 rpx 折算成 px（÷2）再套进 `preview-index-magnet.html`，样式跟真机同一份，不要在预览里手抄一套。

### 「这门课的任务没显示」怎么查

按顺序看三处，一眼能定位：

1. **抓取明细**（账号页「抓任务并上传」的结果）现在每门课后面都标了待做数，例如 `汇编语言: 作业 3（待做 1）`。如果根本没有这一行、或写着 `失败`，那就是抓取阶段的问题，明细里会带原因。
2. **首页的课程筛选行**：任务多的时候按截止时间分组的「一周内 / 更晚」很容易漏看某门课，第二行芯片直接点课程名就能只看这门课。
3. 明细里有、课程筛选点进去却是空的 → 说明**云端还是上一次的旧数据**（上传发生在修复之前）。重新点一次「抓任务并上传」，再回首页下拉刷新。

顺带一提：截止时间在 7 天以后的未完成任务会落在「更晚 / 无期限」分组排在下面，不是丢了。

### 手动标记完成（长按任务）

长按首页任意一条任务，弹出底部菜单：

- **标记为已完成** —— 状态写成 `done` + `manualDone: true`，任务立刻移到「已完成」分组，并把该分组自动展开，不会凭空消失
- **恢复为待完成** —— 已完成的任务长按就是这个；`manualDone` 一起清掉
- **查看详情 / 复制任务链接**

关键是 `manualDone` 这个标记：`store.replacePlatformTasks()` 在替换某平台任务时会先把 `manualDone` 的 externalId 收集起来，**下次同步即使平台那边还显示未完成，也照旧保持已完成**——也就是你要的「用我的判断覆盖平台状态」。反过来，如果平台自己也标记了完成，那就是普通的 `done`，你在小程序里恢复成待办后，下次同步会被平台重新改回完成（这是对的，平台确实完成了）。

接口不用改云函数：`toggleTask` 早就有了（详情页一直在用）。

### 登录设置入口

首页右上角「⚙ 登录设置」直接跳到账号页（就是绑定学习通 / 希冀 / U校园 那页），不用先点平台卡片。页面标题也从「绑定学习平台」改成了「登录设置」。

这一页最下面新增 **「课表导入」** 卡片，两种方式切着用：**统一身份认证**（默认，外网可用）+ **教务系统直连**（仅校园网）。学号 + 密码 → 「登录并导入课表」，要验证码会当场把图显示出来让你填。抓到的课表直接写进「课表」页，同时把开学日期校准好。详见后面 [从学校系统导入课表](#从学校系统导入课表郑州大学)。

### 学期：默认只看本学期，往期任务收起来

超星里往期的课不会消失——秋季学期照样挂着上学期的班，那些班的未完成作业、章节点会一直混在列表里，越积越多。

现在的做法：

1. **抓取时给每条任务标学期**。超星课程接口里带 `content.beginDate`（教学起始）、`course.data[].createtime`（建课时间）和 `content.isretire`（是否结课）。用开始时间的落点推学期：8 月～次年 1 月 = 秋季，2～7 月 = 春季。7 门课实测：

   | 课程 | 开始时间 | 判为 |
   |---|---|---|
   | 汇编语言 | 2026-09-02 | **2026-2027 秋（本学期）** |
   | 软件工程导论 | 2026-03-05 | 2025-2026 春 |
   | 大学物理A(I) | 2026-02-04 | 2025-2026 春，且已结课 |
   | 大学生心理健康教育 | 2025-09-11 | 2025-2026 秋 |
   | 数据结构（2026春季） | 无，靠课名 | 2025-2026 春 |
   | 大学英语（III） | 2022-09-05 | 2022-2023 秋 |

2. **首页默认「本学期」**。有多学期数据时，平台芯片上方多一行学期芯片：`2026 秋 本学期 (5)` / `全部学期 (51)`，点一下就能翻往期。切到「全部学期」时，往期任务会挂一个灰色的学期小标签（如 `2026 春`）。

3. **往期但快截止的仍会显示**。上学期留的作业这周要交，正是最该提醒的——因为规则里加了「截止时间还没到就照常显示」。实测大学英语的 `Quiz 3`（2022 秋的课）截止 10/28，就靠这条规则留在了本学期视图里。

4. 三个平台抓取时都会打学期标签：超星和 U校园按课程开始时间，希冀按课程 `start_date`（没有就认课程名里的「2026春季」这类字样）。**实在判断不出的才一律算本学期**，不会被藏掉。

学期规则集中在 `cloudfunctions/studyHub/lib/semester.js`，`miniprogram/utils/semester.js` 是它的副本（两边要一起改，`node test/semester.js` 有 21 项断言守着）。

### 本地代理（学习通抓不到课程时首选）

云函数出口是腾讯云机房 IP，超星对这类来源很敏感，典型症状是「扫码/绑定都成功，但一抓课程就返回 `请重新登录`」。

`localserver/server.js` 把同一套抓取逻辑搬到你自己电脑上跑：

```bash
node localserver/server.js        # 或双击 localserver/启动代理.bat
```

然后浏览器打开 <http://127.0.0.1:7788/>，页面本身就是一个扫码控制台——生成二维码、扫码、抓课程列表、抓全部任务，全在网页里完成，**不依赖小程序**。

链路通了之后，再在小程序「账号绑定 → 学习通 · 本地代理」里填 `http://127.0.0.1:7788`，点「扫码登录」→「抓任务并上传」，任务会自动写进云端，首页 / 统计 / 每日提醒照旧。

| | 云函数扫码 | 本地代理 |
|---|---|---|
| 出口 IP | 机房 | **你家宽带 / 校园网** |
| Cookie 存哪 | 云数据库（AES 加密） | **只在你电脑内存** |
| 每天 21:30 自动抓 | 能 | 不能，只在你点的时候抓 |
| 电脑要开着吗 | 不用 | **要** |

注意：`localserver/session.json` 存着明文登录态，已写进 `.gitignore`，别外传；代理用完记得关窗口。详细步骤见手册 **第 10.6 步**。

**双击 `启动代理.bat` 没反应 / 黑窗口一闪就没？**

| 症状 | 原因 | 处理 |
|---|---|---|
| 双击后窗口闪一下就关 | 端口 7788 已经有代理在应答，脚本走「已在运行」分支。**这是正常的**，旧版会立刻退出所以像没反应 | 新版会停住等你按键，并自动打开控制台。浏览器开 <http://127.0.0.1:7788/> 能用 = 代理没问题。想自己开窗口就先在任务管理器结束所有 `node.exe` |
| 窗口里一堆 `'xx' 不是内部或外部命令` 乱码 | `.bat` 存成了 LF 换行，cmd 会切错行 | 本仓库已是 CRLF；自己改过就用 VSCode 右下角把换行符切 `CRLF` |
| 提示「没找到 node」 | Node 不在 PATH | 装 LTS 版 Node.js，装完关掉所有命令行窗口重开 |
| 双击完全没窗口、连 `launch.log` 都没生成 | 系统层面拦截（杀软/组策略） | 改用 `start-proxy.cmd`（ASCII 文件名），或在文件夹地址栏输 `cmd` 回车后敲 `start-proxy.cmd` |

每次启动都会把过程写进 `localserver/launch.log`（已 gitignore）。**双击后如果还是觉得没反应，先看这个文件**：有它 = 脚本确实跑了，看最后一行写的是「代理已在运行」还是「没找到 node」；没它 = 脚本根本没被执行。

脚本会先探测 `http://127.0.0.1:7788/ping`：**已经在跑**就提示并打开控制台并停住，**端口被别的软件占着**才报错，不会再出现「双击后什么都没发生」。

### U校园 扫码（只能走本地代理）

U校园 网页端登录跳的是 `sso.unipus.cn`，它支持「UNIPUS 产品 App 扫一扫」，但**扫码结果是用 socket.io 长连接推回来的**（`wss://umcs.unipus.cn/umcs/`），轮询接口被服务端关掉了（只会返回 `Transport unknown`）。所以：

- 扫码只能在本地代理里做，云函数那套老 Node 连不了长连接；
- 代理要多两个依赖（`ws`、`qrcode`），`启动代理.bat` 第一次运行会自动 `npm install`；
- 二维码里的内容由代理生成（`/sso/7.0/sso/code`），你扫完点确认，代理收到 `login` 事件后用 `openid/tgt/jwt` 换回 U校园 的会话 cookie，然后照常存进云端。

浏览器调试用：`POST /up/qr/start` 拿二维码、`POST /up/qr/poll {token}` 查进度。

### 记事本（仿 vivo 便签，纯本机功能）

首页「平台概览」下面有两个小工具入口，左边就是记事本。

- **列表页**：宫格 / 列表两种视图（右上角切换，选择会记住）、搜索框、长按菜单（置顶 / 复制 / 删除）、右下角悬浮新建
- **编辑页**：只输入就自动保存（停手 0.7 秒落盘，退出时再存一次），底部工具栏能换底色（6 种）、置顶、复制、删除
- **空便签自动丢弃**：新建后什么都没写就退出，列表里不会多出一条空白便签；把已有便签内容清空等于删除
- **标题兜底**：不写标题时，列表直接用正文第一行当标题，摘要从第二行开始

数据存在 `wx.setStorageSync('notes_v1')`，**只在本机**，不占云端额度也不联网。

排序规则：置顶的排最前，其余按最后修改时间倒序。时间戳是**单调递增**的（同一毫秒连存两条也会分先后），否则连点两下保存排序会乱。

### 专注（仿番茄 ToDo，纯本机功能）

首页右边那个入口。

- **番茄钟**：默认 25 分钟专注 / 5 分钟休息；圆环走的是 canvas 2d，剩余时间不走 setData 而是直接重绘，省电
- **圆环当旋钮转**：还没开始时按住圆环绕圆心转，一下一下地加时间（顺时针 = 加，一整圈 = 59 分钟），弧尾的白心指针跟着手指走，每 5 分钟轻震一下。为什么不是「横着拖」：圆是圆的，横拖是条直线，在圈的下半部分往右拖时圆的顺时针恰好是往左走的，怎么调正负号都有一半圆用着别扭。按在圆心的大字区域则是横滑条（右 = 加），手指离圆心太近时角度本来就乱跳。拖到 0 点「开始专注」会被拦下，提示先选时长
- **时长随便填**：底部「15 / 25 / 45 / 60」是常用值，右边那颗「自定义」能把专注（1~180 分钟）和休息（1~90 分钟）改成任意整数；设置面板里点中间那个分钟数也能改。填完即存成下次默认值，从计时器进去的话直接按新时长开跑
- **可暂停可放弃**：暂停时把剩余毫秒固化下来，继续时按剩余重算结束时刻。**放弃后直接回到「准备专注」**（按钮变回「开始专注」、圆环变回表盘），并且停在刚才那个分钟数上，不会卡在「继续 / 放弃」
- **待办清单**：点圆圈打勾、点整行直接开始专注（关联这个任务）、长按删除；每专注完一轮，对应待办自动 +1 个 🍅
- **每条待办都得有标签**：学习 / 休息 / 生活，加待办时不选会被拦下；列表上的彩色胶囊点一下就能换分类（改完的标签只影响之后记的时长，已经记下的不追溯）
- **今日概览**：今日番茄数 / 专注分钟 / 休息分钟 / 连续天数 + 目标完成度（一条进度条），在顶部
- **学习 / 休息 / 生活 三块统计**：卡片右上角直接切，每块都有今天 / 本周 / 本月 / 今年四格，配一张柱状图（日 / 周 / 月 / 年，可点切换），最后一根柱子高亮为当前这一格
- **生活时长按关键词再分一层**：切到「生活」时，图下面会多出一组排行条，按待办标题里认出来的活动分（健身房、跑步、做饭、遛狗…），认不出就用标题本身当关键词。时长精确到**几分几秒**，因为生活都是零碎时间，按分钟四舍五入会糊成一片
- **自动休息**：设置里可以打开，专注完直接进休息，不弹窗

**时间一律按秒存**：`sec` 是唯一的口径，展示时再决定给不给秒（学习/休息四舍五入到分，生活给到「3 分 20 秒」）。按分钟存的话，20 秒的碎片会被记成 0。

**休息也算数**：休息走完同样记一条记录（`mode: 'break'`），进休息时长统计，但**不占番茄数、不算连续打卡**。中途「放弃」的休息不记——只有完整走完才算，和专注一个规矩。

**计时为什么不用「每秒减一」**：小程序切到后台会被挂起，累加必然走偏。这里记的是**结束时刻 `endAt`**，每次刷新拿 `Date.now()` 去减；暂停时把剩余毫秒存下来，继续时再换算新的 `endAt`。所以切后台、锁屏、去别的页面转一圈回来，时间都是准的。

计时器状态在 `tomato_run_v1` 里，**离开页面不会丢**：从专注页返回首页，再点进来会接着走；这一轮早该结束了的话，进来时会补记并提示（离开超过 2 小时则不记录，免得昨天开的计时今天冒出来一个）。

数据键：`tomato_tasks_v1`（待办，带 `tag`）、`tomato_sessions_v1`（记录，专注和休息都存，最多留 500 条）、`tomato_days_v1`（按天汇总：`{ study: {s,n}, rest: {s,n}, life: {s,n} }`，`s` 是秒、`n` 是次数）、`tomato_settings_v1`（设置）、`tomato_run_v1`（正在跑的那一轮）。

**为什么多存一张 `tomato_days_v1`**：明细只留 500 条，一天 5 个番茄也就撑三个月，「今年学了多久」会被这条上限悄悄截断。所以每记完一轮就往按天汇总表里加一笔（一天一个键，一年才 365 个键），日/周/月/年都从这张表算。老数据不用手动迁移：第一次读表时如果发现没有，会拿明细汇总一遍补上；更老的表只有 `min/pomos`，读的时候会用明细把休息补回来（学习时长以表里为准，不会被明细的 500 条上限削掉）；再往前的 `min/pomos/rest/rests` 四字段版本也会在读取时折算成三块结构，写完立刻落盘。

### 访客账号（其他人员用手机号注册）

不是郑大学生、或者只是想把番茄钟和便签当个顺手工具用的人，在登录页顶部把那排页签从「本校学生」切到「其他人员」，用**手机号 + 自设密码**注册就能进。**不需要短信验证码**，填两遍一致就注册成功——省一条短信费用，也不用等模板审核。

- **注册**：手机号（服务器会去掉 `+86`、空格、连字符，全角数字也认）+ 密码（6~32 位）+ 昵称（可不填，默认「用户 8000」这种按手机号尾号起名）
- **登录**：手机号 + 密码。连错 5 次锁 10 分钟，第 6 次会告诉你还剩几分钟——计数写在数据库记录里，重装小程序也不算清零
- **能用的**：记事本、专注（番茄钟 / 待办 / 学习与休息统计）、手动课表（粘贴导入、一节一节加）、自己建的任务、订阅提醒、首页看板
- **不能用的**：所有**必须用到学号或学校系统**的东西 —— 郑大统一认证、教务导入课表、学习通 / 希冀 / U校园 / 雨课堂的绑定与同步、任务推送、账号自检与扫码登录

为什么这么切：访客没有学号，上面这些功能就算把入口给他也一定失败（要 CAS 票据、要课程 ID），与其报一堆看不懂的错，不如直接说清楚「这是学校功能」。

**有一个刻意的例外**：`zzuAuto` / `zzuMfaVerify`（统一认证登录）不在 `SCHOOL_ONLY` 里，而是单列在 `LOGIN_ANY`。它们是「证明你是学校的人」这一步本身，不查账号、不读课表、不碰 `zzu_sessions`。把登录本身也拦掉的话，访客想换成学校账号会在第一步就 403，而访客又退不出去——两边都走不通。认证通过后云端会当场 `markSchool` 把身份切成学校账号。

**边界在云端，不在界面上。** 前端把入口藏起来只是体验，真正的闸门是 `cloudfunctions/studyHub/lib/permissions.js` 里那份 `SCHOOL_ONLY` 清单：`index.js` 在每个请求进来时先查一次身份，命中清单里的接口直接返回

```js
{ code: 403, message: '访客账号只能用记事本、专注和手动课表' }
```

清单只此一份，云端拦截和 `node test/auth.js` 用的是同一个数组，不会出现「前端藏了、云端忘了」这种半吊子权限。

**老用户不受影响**：`users` 集合里**查不到记录**的微信一律按 `school` 处理（连查库出错也按老用户放行）。新增权限层不能把已经在用的人关在门外。

退出入口有两个：**首页最底部**的按钮（访客是「退出访客身份」），和**导航栏右边那个身份胶囊**（访客点它弹「当前是访客身份 → 退出登录」）。底部那个放在所有 `wx:if` 分支之外：早先它写在「任务分组」那个 block 里，而访客没有平台账号、`hasAccount` 为 false 时走的是空态引导卡，整个 block 不渲染，页面上就**根本没有退出按钮**。

身份切换有五条规矩，都是为了不把账号搞丢：

| 场景 | 结果 | 为什么 |
| --- | --- | --- |
| 当前微信已绑学校账号，再去注册访客 | 拒绝，提示直接登录 | 一个微信只能是一个身份 |
| 当前微信已绑学校账号，用手机号登录访客 | 拒绝，提示先退出 | 否则会覆盖掉 `school` 记录，课表配置凭空消失 |
| 访客点退出 | 记录保留，只打 `loggedOut` 标记，身份变成 `anonymous` | 整条删掉 / 解绑 openid 的话，云端就认不出他是谁，会按老用户放行成学校账号——刚退出就看到了学校数据 |
| 同一微信上已有访客号 A，再登访客号 B | A 没退出就拦住（提示先退出）；A 已退出则只解绑 A、记录留着 | 不能静默删掉 A，否则那个手机号就再也登不回来了 |
| 访客换成学校账号 | 先退出（变 `anonymous`）再认证 | `markSchool` 对**正在登录中**的访客直接拒绝；已退出的可以升级 |

### 数据怎么隔离（访客看不到学校那份）

这是最容易漏的一层，而且是真出过的 bug：**小程序只有一个 openid**。同一个微信先登学校账号、再切访客，`openid` 一模一样——如果数据只按 openid 存，访客会把学校账号的任务、课表、便签全盘接收。

所以所有数据都按「**归属键**」隔离，`users.ownerOf(openid, role)`：

| 身份 | 归属键 | 效果 |
| --- | --- | --- |
| `school` | `openid`（裸的） | 存量数据本来就是它，**一行都不用迁** |
| `guest` / `anonymous` | `'g::' + openid` | 天然落在一片空白里，什么都查不到 |

两处都要做，缺一个就漏：

- **云端**（`accounts` / `tasks` / `reminders`）：`index.js` 入口算一次 `owner`，往下所有 `store.xxx()` 都传它，不再传裸 `openid`。字段名仍叫 `openid`，但存的是归属键——所以 `lib/store.js` 的参数特意改名成 `owner`，注释也写着「别把裸 openid 丢进来」。
- **本机**（`timetable_v1` / `notes_v1` / `tomato_*`）：`miniprogram/utils/scope.js` 的 `SCOPE.key(name)`，学校态返回原名、访客态加 `g::` 前缀。**每次读写都要算**，不能在模块顶层算好存常量——身份是会变的。

这样切换身份就是一个干净的开关：学校账号看到自己那份，访客看到自己那份，互相看不见，也不会丢。访客换了微信登录同一个手机号，服务端会把 `g::旧openid` 下的数据整体搬到新键（`store.moveOwner`），不会白装一次。

还有一层兜底：**前端也按身份过滤一遍**。`index.js` 的 `applyData` 里，非学校身份只保留 `platform === 'custom'` 的任务（平台任务只能由同步产生，而同步是学校功能）。这一层不是正路——正路是云端就查不到——而是防「云函数忘了重新部署」：只改前端不传云函数时，云端仍会按裸 openid 把学校任务吐出来，前端这一刀能立刻拦住，同时在首页顶一条红字提醒去重新部署（`verWarn`），不会让人先看到别人的数据再等修复。

`users` 集合一条记录长这样：

```js
{ openid, role: 'guest' | 'school', loggedOut /* 访客退出后为 true */,
  phone, pwdHash, salt, nickname,
  username /* 本校的学号 */, createdAt, lastLoginAt, failCount, lockUntil }
```

安全上守三条：

1. **不存明文密码**：只存 `sha256(salt | 密码 | PEPPER)`，`salt` 每条记录单独随机生成（16 字节），`PEPPER` 是写死在服务端的常量。拿到数据库也没法拖库反查
2. **不出库**：对外只返回 `publicProfile()`，`pwdHash` / `salt` 从不出库，手机号一律打码成 `138****8000`
3. **不靠内存计数**：`failCount` / `lockUntil` 写在记录里，云函数冷启动、多实例并发都不会被绕过

`users` 是第 5 个集合。首次注册时如果它还不存在，云函数会自己 `createCollection` 建一个（权限记得设成「仅管理端可读写」，别让客户端直接读密码哈希）。

### 课表（本机功能，不走云端）

课表存在 `wx.setStorageSync('timetable_v1')`，是**本机数据**，换手机不同步（云同步可以加，但不紧急）。
数据来源有三种：**从郑大教务系统直接导入**（见下一节，最省事）、粘贴导入、手动一节一节加。

课表页是**周网格视图**（和校园集市那类 App 一样）：左边一列节次，右边七列周一到周日，课程按「第几节到第几节」占格，占几节就多高，点一下看详情、长按删除。

`utils/schedule.js` 里的解析器认这些写法：

```
周一 1-2节 汇编语言 松园3-201 1-16周
星期二,第3-4节,大学英语,北3-105 1-16周(单)
礼拜三 5-6 数据结构@松园2-301 1-8周
四 7-8节 软件工程导论
周五 9-10节 军事理论 双周
```

**周次**（`1-16周` / `第1-16周(单)` / `双周` / `3周`）是可选的，写了就按周次过滤：翻到第 8 周，`1-8周` 的课还在，第 9 周自动消失；单双周同理。不写就按每周都上。

开学日期在课表页右上「设置」里选一下（存 `timetable_term`），右上角就能算出「现在是第几周」。

顶部还有 `‹ 第 7 周 ›` 可以翻别的周，「回本周」一键跳回来。

首页顶部会显示今天有几节课（也按周次过滤，单双周不会串），正在上的那节标红，下一节写出来。

`node test/schedule.js` 跑解析 + 网格 45 项断言；`node gen-preview-schedule.js` 会按真实算法生成 `preview-schedule.html`，用浏览器打开可以核对网格定位。

### 从学校系统导入课表（郑州大学）

> 「课表」页 → 底部「🏫 教务导入」；凭据填在「登录设置 → 课表导入」

**整条链路跑在云函数里，手机上单独就能完成，不需要电脑。** 两条路：**统一身份认证（推荐，纯手机可用）** → 教务系统直连（仅校园网 + 电脑代理，几乎用不到）。

#### 路线 A（推荐）：统一身份认证 → 门户课表

2026-10 实测出来的结论，先说清楚为什么这条能通、且能搬上云端：

| 地址 | 公网可达 | 说明 |
|---|---|---|
| `cas.s.zzu.edu.cn` 统一身份认证 | ✅ 通 | 从家里、手机流量、云函数机房都能登 |
| `info.s.zzu.edu.cn` 综合信息门户 | ✅ 通 | 门户的「我的日程」里有教务同步过来的课表 |
| `jw.v.zzu.edu.cn` 教务系统 | ❌ 不通 | 443 端口只对校园网开放，公网 TCP 直接超时 |

关键在于门户（苏亚星 supwisdom 系统）的服务端已经把教务课表聚合过来了，
接口是 `portal-api/v1/calendar/share/schedule/getEvents?startDate=&endDate=`。
所以我们不需要碰教务系统，只要拿到门户的登录态就行 —— 而 CAS 和门户都是公网可连的，
所以登录 + 抓课表这整件事都放在云函数里跑，小程序只负责填一次学号密码。

> 之前为了绕开「教务系统只开校园网」，把这条链路放进了电脑上的 `localserver`。
> 现在已整体搬到云端（`cloudfunctions/studyHub/lib/zzu.js`），那个代理只留给学习通扫码备用，课表不再依赖它。

**关键事实（2026-10-24 定稿，整条通道已换成「郑大 APP 的 /token/ API」）**：

网页版 CAS 有三个死结：强制短信二次验证、CASTGC 只管 14 天、**网页 ticket 塞给门户 API 直接被拒**
（门户是 Sa-Token，只认 APP 下发的 idToken —— 这就是之前「无效token」卡死的根因）。
所以整条通道换成了郑大 APP 在用的 `/token/` 纯 JSON 协议（协议来源：开源项目
[Illustar0/ZZU.Py](https://github.com/Illustar0/ZZU.Py) 的抓包逆向，逐条核对过）：

```
小程序填学号 + 密码 → 云端 GET /token/jwt/publicKey（拿 RSA 公钥）
        ▼
POST /token/mfa/detect?username=<__RSA__加密账号>&password=<__RSA__加密密码>&deviceId=<设备号>
        │  返回 {state, need, mfaTypeSecurePhone}
        ▼
need=false（设备已被信任 / 账号没开 MFA）→ 直接走 passwordLogin
need=true → GET /token/mfa/initByType/securephone?state=...
             │  返回 gid + attestServerUrl + 打码手机号
             ▼
           POST {attest}/api/guard/securephone/send {gid}   ← 短信发到你的手机
             │  （deviceId / mfaState / gid / 账号密码密文 存进 zzu_sessions 接力）
             ▼
           小程序弹出「短信验证码」输入框 → 填验证码
             ▼
           POST {attest}/api/guard/securephone/valid {gid, code}   ← status===2 才算过
             ▼
           POST /token/password/passwordLogin?...&mfaState=<同一个 state>
             │  → {idToken, refreshToken}
             ▼
           idToken 存库（约一个月免密）→ 拉教务课表 → 写进 timetable_v1
```

**课表数据源（2026-10-24 定稿）**：不走门户的聚合接口（字段无对外文档，
之前「门户返回了数据但没解析出课程」就是栽在它身上），直接走**新本科教务系统**
`jwxt.zzu.edu.cn/eams-micro-server`（公网可达，校园集市同款数据源）：

```
GET /api/v1/semester/current-semester          → 学期号
GET /api/v1/lesson/student/course-table/<学期号>
    认证：Authorization: <idToken> + cookie userToken=<idToken>
    返回 data[].course.nameZh + data[].schedules[]
    （date / weekday / startUnit / endUnit / weekIndex / room.nameZh）
```

拍平规则：同一门课的几十条排课记录按「周几 + 起止节 + 课程名」聚合成格子，
周次取出现过的教学周范围；开学周一由 weekIndex===1 的那节课日期反推（比教学周
接口更准）。

- **idToken 约一个月有效，refreshToken 约两个月**，比网页 CASTGC 的 14 天长一倍不止；
  **MFA 信任绑定 deviceId**（首次登录生成后固定），验证过一次之后，同一设备再登录
  不再收短信 —— 到期续登只要密码不要验证码。
- 账号和密码都走 RSA 加密（PKCS#1 v1.5 + `__RSA__` 前缀，公钥来自
  `/token/jwt/publicKey`，不是网页那个 `/cas/jwt/publicKey`）。
- 密码密文只在 MFA 等待期间落库（RSA 外再套一层 SECRET 加密），验证完成立即清掉；
  接力态超过 10 分钟（`FORM_TTL`）作废。
- 短信发不出去（没绑安全手机）→ 明确报「没绑安全手机」，不谎报「验证码已发送」。

#### 路线 B（备选）：教务系统直连，仅校园网

> 「课表」页 → 底部「🏫 教务导入」

郑大本科教务系统是 **EAMS**（复旦 URP 系），入口 `https://jw.v.zzu.edu.cn/eams/login.action`。
它有两个客观限制，决定了不可能做成「小程序里输个密码就完事」：

| 限制 | 后果 | 我们的应对 |
|---|---|---|
| 基本只对校园网 / 校园 VPN 开放（实测公网直连 `UND_ERR_CONNECT_TIMEOUT`） | 机房 IP 的云函数 100% 抓不到 | 只能在**你连了校园网的电脑**上抓 |
| 登录页有图形验证码，另一入口走统一身份认证（要短信验证码） | 没法全自动登录 | 验证码图片直接显示出来给你填；短信那条路留给 Cookie 兜底 |

所以真正登录的动作放在**你电脑上的本地代理**里做，小程序只负责「填一次学号密码 → 点一下」。

链路是这样（两条入口，最后都落到同一份解析器）：

```
入口 A（推荐）小程序「登录设置 → 教务系统」
        学号 + 密码（+ 验证码，有就弹图让你填）
              │  POST /jw/auto
              ▼
入口 B  浏览器开 127.0.0.1:7788，控制台第 3 块「教务课表导入」
              │  /jw/probe → /jw/login → /jw/schedule
              ▼
        本地代理登录 EAMS，抓课表页
              │
              ▼
        解析成结构化课程 ──► 小程序「课表」页（写入 timetable_v1 + 校准开学日）
```

**为什么教务不能像希冀那样让小程序直连？**

1. 上线后只允许访问配置过的 HTTPS 白名单域名，`http://192.168.x.x` 这种内网地址进不去（正式版无解，开发版/体验版勾了「不校验合法域名」才行）；
2. 教务的验证码 + CAS 跳转链条长，还要短信二次验证，一次跑完容易超时，交给电脑上的代理更稳。

> 顺带更正一个以前的说法：`wx.request` **是能读到** `res.header['Set-Cookie']` 的（微信会把多条用逗号拼成一个字符串，`Expires` 里也有逗号，得按「像 `name=value` 才算新的一条」来拆）。小程序只是不会**自动**保存和回传 Cookie，自己存、自己带就行——希冀内网直连就是这么做的，所以那边已经不需要手工粘 Cookie 了。

所以「在小程序里输密码」这一层是我们做的，真正握 Cookie 的那一层在代理里。用起来感觉是一样的：填一次，以后点「拉取课表」就行。

密码去向：存在手机本地（`jw_cred_v1`，做了简单混淆），**不上云**；点导入时传给局域网里的代理，代理当次用完就丢，**不写电脑磁盘**。教务登录态（Cookie）只留在代理进程内存里，30 分钟没动就过期。

`localserver/eams.js` 里做了什么：

- **探测**：先看这台机器能不能到教务系统、登录页要不要验证码、是不是只支持统一认证。报错会直接告诉你「连 ZZU-WLAN / 开 VPN」而不是丢个 `fetch failed`。
- **登录**：`POST /eams/login.action`，字段名从登录页里现抓（各校叫法不同）；密码先按明文提交，失败再按 MD5 试一次（有的学校前端会先加密）。
- **抓课表**：不硬编码单一接口 —— 依次试 `ws/schedule/table`（新版 JSON）、`courseTableForStd!courseTable.action`（表格页）、入口页内嵌表格，谁先返回能认的内容就用谁。探测轨迹会打印出来。
- **解析**：EAMS 每个格子自带「周二第1,2节{第1-16周}」这种短文本，拍平成 `周二 1-2节 高等数学 二教101 1-16周`，再交给 `utils/schedule.js` 里同一套 `parseLine` —— 手动粘贴和教务导入永远同一个行为，一份逻辑两处用。
- **学期与开学日**：顺手把学期下拉框和「开学」日期挖出来，导入时自动校准 `timetable_term`，周次和单双周立刻对齐，不用你手动设。

**登录不上还有两条兜底**（控制台同面板里）：

1. **Cookie**：浏览器里正常登录教务系统 → F12 → Network → 任意请求 → 复制 `Cookie` 整串 → 粘贴。
2. **源码**（完全离线，连校园网都不用）：浏览器打开课表页 → 右键查看网页源代码 → 全选复制 → 粘进「离线解析这段」。解析完点「复制导入文本」，粘到小程序「课表 → 粘贴导入」，格式完全通用。

登录态（Cookie）只存在代理进程的内存里，**不落盘、不上云** —— 教务 Cookie 能看成绩、能选课，比学习通更敏感。

`node test/eams.js` 跑 45 项解析断言（标准结构、变体写法、一格多课、脏数据、JSON 课表、学期下拉、开学日）。
`node test/cas.js` 跑 73 项（RSA 加解密往返、登录页字段识别、JWT 解 ticket、钟点→节次、门户日程拍平、取数范围）。

### 第一次跑的正确姿势

1. **学习通先用「扫码登录」**。账号绑定页展开学习通，首次绑定默认就是扫码模式：
   - 在**微信开发者工具**里打开账号页，二维码会显示在电脑屏幕上
   - 手机打开「学习通」App → 右上角「扫一扫」→ 对着电脑屏幕扫
   - 手机上点「确认登录」，小程序这边 1~2 秒内自动完成绑定并同步
   - 全程不碰 DevTools，也不用复制任何 Cookie
   - 二维码 4 分钟过期，过期点「刷新二维码」重新来一张

2. **希冀、U校园用 Cookie 模式**，不要一上来试密码。Cookie 模式跳过了所有加密和风控，成功率最高。
   - 电脑浏览器登录对应平台 → F12 → Network → 点任意一个请求 → 复制 Request Headers 里的 `Cookie` 整行 → 粘到小程序里。
   - 粘整条「复制为 cURL」命令也行，小程序会自动把 `cookie` 头抽出来。

3. 在小程序里保存并同步，看弹窗报错。
4. 如果报「读到课程但没解析出任务」，去云开发控制台 → 云函数 → `studyHub` → **日志**，看具体是哪一步没命中。
5. 按实际页面调整对应适配器里的解析正则（每个适配器顶部都有流程注释）。

### 学习通报「请重新登录」怎么定位

这是最容易卡住的一步，注意它和「Cookie 少了字段」是两件事。报错文本现在会自带排查轨迹，形如：

```
读取课程失败（Cookie 字段：JSESSIONID,route,_uid,_d,uf）｜
课程接口说「请重新登录」×2；mooc1.chaoxing.com 被跳登录页；i.mooc.chaoxing.com 被跳登录页；
[换精简 Cookie 再试]；课程接口说「请重新登录」×2
```

- `被跳登录页` 表示带着这个 Cookie 访问课程页，被 302 踢回 `passport2` 登录页 —— 说明服务端压根不认这个登录态。
- 代码会自动用**两套 Cookie** 各试一次：完整版，以及去掉 `JSESSIONID`/`route` 的精简版（补全登录态的过程中，不同域名会各发一个同名 JSESSIONID，扁平 cookie 串里会互相覆盖，带着错的会话号请求就会被判未登录）。

如果两套都不行，点账号卡片上的 **「网络自检」**：它会拿你的 Cookie 用**你自己手机的网络**直连一次接口，弹窗里对比「课程接口返回什么」和「课程页有没有课程链接」，就能分清是 Cookie 有问题，还是云函数机房 IP 被区别对待。左下角「复制详情」可一键复制结果。

### 校园内网版希冀（`10.x` 私有地址）

`10.67.4.14` 这类地址是 RFC1918 私有网段，**云函数永远访问不到**，所以这个平台的抓取搬到了客户端：

```
手机（连校园网）── wx.request ──► http://10.67.4.14   抓任务 + 本地解析
        └───────── pushTasks ──► 云数据库 ──► 首页 / 统计 / 每日提醒
```

- 实现在 `miniprogram/utils/edu.js`：配置（地址 + Cookie）只存本机 `wx.setStorageSync`，**不上传云端**
- 云端新增 `pushTasks` 动作接收结果；这类账号 `mode: 'intranet'`，云函数同步和定时任务会**主动跳过**，不会被误标成「登录已失效」
- 只能 Cookie 模式：`wx.request` 拿不到 `Set-Cookie`，没法维持 session，密码登录做不了
- 前提：设备连校园网 + 开发者工具勾「不校验合法域名」（`http` + IP 过不了正式版校验）
- **同步时机**：首页那颗「同步全部课程和任务」会把希冀一起抓（`miniprogram/utils/syncall.js`）。之所以不能只靠云端：云端 `handleSync` 会把 `intranet` 账号过滤掉，只调云端的话希冀永远停在「上次直连同步」的样子。现在的做法是**两路并发**——希冀走本机直连（和账号页「直连同步」同一条路，抓完 `pushTasks` 上传），学习通 / U校园走云函数，结果按平台合成一张表弹出来（每个平台多少条、几条已完成、哪条失败）。账号页里希冀卡片上的「立即同步」也会自动转成本机直连，不会再回一句「已跳过」

### 各平台改哪里

- **学习通**：`adapters/chaoxing.js` 的 `parseWorkHtml()` 和 `parseTaskPointHtml()`。想要原始 HTML 就在这两个函数里加一行 `console.log(html.slice(0, 3000))`，看日志里真实结构长什么样，再对着改正则。

## 五、它是怎么工作的

```
小程序          云函数 studyHub               三个平台
  │                   │                          │
  ├─ saveAccount ────► 加密存库                    │
  │                   │                          │
  ├─ syncTasks ──────► 读账号 → 解密               │
  │                   ├──── 登录 + 抓取 ────────► │
  │                   │◄─── 任务列表 ──────────── │
  │                   ├─ 覆盖写入 tasks（保留手动勾选）
  │◄── 结果 ──────────┤                          │
  │                   │                          │
  ├─ getDashboard ───► 查库返回账号 + 任务
```

- **凭据存储**：AES-256-GCM 加密后入库，按 `openid` 隔离，云函数返回给前端时永远剔除凭据字段。
- **覆盖式同步**：每次同步先删该平台旧任务再写新的，但会记住你手动勾选过的完成状态（`manualDone`），不会被平台数据覆盖。
- **串行抓取**：三个平台一个接一个抓，不并发，降低被风控的概率。
- **扫码会话不落库**：学习通的 `uuid`/`enc`/临时 cookie 打包 AES 加密成一个 token 交给前端，轮询时原样带回来。云函数完全无状态，冷启动、多实例都不会丢会话，也不用为它多建一张表。
- **先认身份，再进业务**：每个 action 落到 `switch` 之前，先按 `openid` 查 `users` 定角色（查不到记录 = 本校学生），是访客又命中 `SCHOOL_ONLY` 就直接 `403` 返回，一行业务代码都不执行。所以权限不是靠前端藏按钮，改前端也绕不过去。

## 六、已知限制

1. **打不开外部网页**。小程序 `web-view` 要求企业主体 + 域名备案 + 业务域名白名单，个人主体配不了。所以任务详情页只提供「复制链接」，需要粘贴到手机浏览器打开。
2. **U校园扫码只能在本地代理里做；任务抓取已按 AI 版 5.0 重写但还没用真账号跑过**。扫码确认结果走 websocket，云函数接不了，所以扫码必须在电脑上开着 `localserver`（Cookie 模式和密码登录不受此限制）。适配器已换成 uai.unipus.cn 的真实接口（路径经开源项目逆向核对、22 项离线测试钉死），但**最终确认还要你绑定后点一次同步**——接口字段万一有出入，把报错和 debug 发我按真实返回微调。
3. **自动同步每小时一次，提醒每晚一次**。云函数定时触发器每小时第 5 分钟拉一次所有绑定平台的最新任务（55 分钟内手动同步过的账号跳过，不给平台风控压力）；订阅消息提醒只在每晚 21 点这一小时发，其他时候只同步不打扰。改频率在 `config.json` 的触发器 cron 里。
4. **订阅消息是一次性的**。微信规则：用户每授权一次只能收到一条，收完要回小程序点「续订」。这不是实现问题，是微信的限制。
5. **Cookie 有效期**。学习通约 30 天，希冀和 U校园更短。U校园要的是**带 sso.unipus.cn 会话的整串 Cookie**（扫码登录保存的就是）。失效后小程序里会标红「登录已失效」，重新绑一次即可。
6. **不要分享账号**。这是给自己用的工具，把账号密码放进第三方服务本身有风险，用 Cookie 模式能把这个风险降到最低。
7. **扫码登录需要「另一块屏幕」**。二维码在小程序里显示，手机得对着屏幕扫——在开发者工具里跑最顺手（手机扫电脑）。真机上则需要另一台设备来显示二维码。用 `localserver` 时可以直接在电脑浏览器里扫码，体验更好。
8. **学习通会把机房 IP 和家宽 IP 区别对待**。同一个登录态，机房 IP 上一律返回「请重新登录」，在你浏览器里却完全可用。这不是 Cookie 的问题，是来源的问题，**服务端抓取这条路走不通**。解决办法就是 `localserver/` 本地代理——用你自己的网络出口抓，抓完把结果回传云端。**2026-10-24 已实测有效**：同一套代码，机房跑不通，本机跑 7 门课全通。下面这些方式都试过且证实无效：补全 cookie 字段、换 Referer、换请求头、精简/完整 cookie 双版本重试。
9. **本地代理要求电脑开着**。它是「按需抓取」，不参与云端 21:30 的定时同步。想要全自动，还是得靠云函数（前提是学习通愿意放行机房 IP）。
10. **课表只存在本机**。`wx.setStorageSync('timetable_v1')`，换设备/清缓存就没了，也不参与云同步。
11. **章节任务点按「章」汇总，不逐小节列**。学习通目录页只给每一章一个「未完成任务点数」，想知道具体是哪个小节的视频，点进去看；每门课最多取 12 章。
12. **课表导入分两条路**。主路「统一身份认证（APP /token/ 通道）→ 新本科教务课表」外网可用：学号密码登录 + 短信验证码在小程序里走完（见「关键事实」的流程图），idToken 约一个月免密、设备信任后不再收短信；数据直接来自 `jwxt.zzu.edu.cn/eams-micro-server`（校园集市同款），依赖它不迁移不鉴权改版，学校一改版 `zzuProbe` 会先报出来。备选路「教务系统直连」走老教务 `jw.v.zzu.edu.cn`，必须连 ZZU-WLAN / 校园 VPN，且可能被图形验证码挡住，那时只剩 Cookie 和源码粘贴两条兜底。**教务接口的字段各版本有差异**，如果解析出 0 条，控制台会打印原始返回的前几个字段名，发我看一下就能对上。
13. **记事本、专注的数据也只在本机**。`notes_v1` / `tomato_*` 都在 `wx.setStorageSync`，换手机、删小程序就没了，也不参与云同步。要做多端同步得再建两个集合，暂时没做（这两块本来就不需要联网）。
14. **专注计时靠前台刷新**。小程序切后台超过 5 分钟会被微信挂起，`setInterval` 停掉，**但时间本身不会错**——回来时按 `endAt` 重算。只有「到点那一刻的震动提示」会因为你不在前台而延后到你回来时才触发，这是小程序的限制，绕不过去。
15. **访客账号没有短信验证，所以手机号没被「验真」**。这么做是为了省短信费、也免去个人主体申请模板的麻烦，代价有两条：① 谁都可以填一个不属于自己的号码注册（同一号码只能注册一次，登进来看不到别人的东西，最多算占位）；② **忘了密码没法自助找回**——没有可验证的手机号，也就没有「重置密码」这条路。真忘了就在云开发控制台 → 数据库 → `users` 里删掉那条记录，再用同一手机号重新注册（原来建的任务按 openid 挂着，会跟着新注册的记录回来）。要真做验证码，接腾讯云短信即可，`lib/users.js` 里加一步校验，其余不用动。
