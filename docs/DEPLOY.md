# 手把手部署手册

从零开始，照着做就行。全部做完大约 30 分钟。

**遇到卡住的地方，先翻到最后面的「常见报错对照表」，90% 的问题都在那张表里。**

---

## 第 0 步：先确认你要准备什么

- 一台 Windows 或 Mac 电脑（手机上做不了）
- 一个没注册过小程序的邮箱（QQ 邮箱、163 都可以）
- 你的身份证（个人主体注册要实名）
- 大约 30 分钟

不需要：服务器、域名、备案、钱。

---

## 第 1 步：注册小程序，拿到 AppID

1. 浏览器打开 <https://mp.weixin.qq.com>
2. 右上角点「立即注册」
3. 账号类型选 **「小程序」**（不是订阅号，不是服务号，别选错）
4. 填邮箱 → 去邮箱收激活邮件 → 点邮件里的链接
5. 主体类型选 **「个人」** → 填身份证姓名和号码 → 用微信扫码做人脸验证
6. 注册完登录后台，左侧菜单找到 **「开发管理」→「开发设置」**
7. 页面上有个 **AppID(小程序ID)**，形如 `wx1a2b3c4d5e6f7g8h`，复制下来备用

> 个人主体完全够用，云开发、订阅消息都支持。唯一不支持的是 `web-view` 打开外部网页，这个后面会说怎么绕。

## 第 2 步：装微信开发者工具

1. 打开 <https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
2. 下载 **「稳定版 Stable Build」** 对应你系统的版本（Windows 64 位 / macOS）
3. 一路下一步装完
4. 打开工具，用**微信扫码**登录（用你注册小程序那个微信）

---

## 第 3 步：导入项目

1. 打开开发者工具，左侧选 **「小程序」**，点右边的 **「+」**
2. 在弹出的窗口里：
   - **目录**：点右边文件夹图标，选到 `study-hub` 这个文件夹（注意是 `study-hub` 本身，不是里面的 miniprogram）
   - **AppID**：粘贴第 1 步复制的 AppID
   - **开发模式**：小程序
   - **后端服务**：选 **「微信云开发」**
3. 点「确定」/「导入」

**你会看到什么**：模拟器里出现了手机界面，显示「课业看板」首页，下面有个「去绑定账号」的按钮。

**同时控制台（下方）会有一堆红色报错**，说 `cloud function not found` 或 `云开发未初始化`。这是**正常的**，因为云函数还没部署，继续往下走。

---

## 第 4 步：开通云开发，拿到环境 ID

### 4.1 关于费用（先看这段，避免多花钱）

云开发在 2022 年取消永久免费版之后，基础套餐是 19.9 元/月。但**腾讯云现在还提供一个免费体验环境**，自用完全够：

- 每个云开发账号可以创建 **1 个免费体验环境**，每月 **3000 资源点**
- 基础付费套餐是每月 40000 点，免费额度相当于 7.5%，你这个用量（一天同步一两次）连零头都用不到
- **单次可续 6 个月，到期前 1 个月手动续期**

有一条必须记住：

> 免费环境在小程序**正式发布上线后**，到期时间会变成「上线后第 15 天」。

所以**别提交审核、别发布**。自己用的话，用「开发版」（扫码预览）或者「体验版」就够了，环境不会到期。

**怎么拿免费环境**（注意别走错门）：

1. **不要**在微信开发者工具里点「开通」，那里建出来的是老套餐版本，会直接引导你付费
2. 浏览器打开 <https://console.cloud.tencent.com/tcb>，微信扫码登录
3. 新建环境 → 类型选 **免费体验版** → 填名字（如 `study-hub`）
4. 创建完成后，复制环境 ID，然后回开发者工具，在「云开发」面板里切换到这个环境

如果你已经不小心建了付费环境，**先别付款**：去腾讯云控制台销毁它，再按上面流程重建免费版。

### 4.2 建好之后拿环境 ID

1. 云开发控制台顶部会显示一串 **环境 ID**，形如：
   ```
   study-hub-8gk2m3n4o5p6q7
   ```
2. **把这串环境 ID 复制下来**

---

## 第 5 步：把环境 ID 填进代码

1. 回到开发者工具，左侧文件树展开 `miniprogram` 文件夹
2. 点开 `app.js`
3. 找到**第 1 行**：
   ```js
   const CLOUD_ENV = 'YOUR_CLOUD_ENV_ID' // TODO: 替换成你的云开发环境 ID
   ```
4. 把 `YOUR_CLOUD_ENV_ID` 替换成第 4 步复制的环境 ID，两边的单引号要保留：
   ```js
   const CLOUD_ENV = 'study-hub-8gk2m3n4o5p6q7'
   ```
5. 按 `Ctrl + S` 保存

---

## 第 6 步：建五个数据库集合

1. 在云开发控制台里，左侧点 **「数据库」**
2. 点集合列表左边的 **「+」** 号，新建集合，名字**逐字**输入：`accounts`
3. 同样的方法再建四个：`tasks`、`reminders`、`zzu_sessions`、`users`
4. 每建一个，点它的名字右侧的 **「权限设置」**，选 **「仅管理端可读写」**（列表里最后一个选项），保存

**逐个确认一遍**：五个集合都存在，权限都是「仅管理端可读写」。

> `zzu_sessions` 是「课表导入」专用的：云端登录郑大统一认证后，把 14 天免密的登录票据加密存这里。等短信验证码的那几分钟里，这里会临时存一份**双保险加密的密码密文**（RSA 密文外面再套一层 SECRET，CAS 会话一失效它就是废纸，验证完成立即删除）。第一次点「登录并导入课表」时云函数也会自动建，但手动先建好并把权限设对更稳。

> `users` 是「这个微信是谁」的登记本：本校学生（`role: 'school'`，记学号）还是访客（`role: 'guest'`，记手机号和密码哈希）。访客账号能用记事本、专注、手动课表，学校相关功能一律拒掉——闸门在云函数里，靠的就是这张表。**你不建也不影响老用户**（查不到记录一律按本校学生处理），但访客注册时会自动建，不如先建好并把权限设对。

> 为什么选这个权限：前端不直接读数据库，所有读写都走云函数。云函数是管理员身份，不受这个限制。这样别人就算知道你集合名叫什么，也一条数据都读不到。

## 第 7 步：部署云函数

1. 回到开发者工具，左侧文件树找到 `cloudfunctions` 文件夹
2. **先把默认环境设一下**：右键 `cloudfunctions` 文件夹 → 能看到「当前环境」之类的选项，选你刚创建的环境
3. 右键 `studyHub` 这个文件夹（**是文件夹本身，不是里面的文件**）
4. 菜单里选 **「上传并部署：云端安装依赖（不上传 node_modules）」**
5. 等 30 秒左右，右下角提示「上传成功」

**怎么确认云端真的是新代码**（这步别跳，最容易「以为传了其实没传」）：

小程序里进首页，往下滑到最底部的灰色小字：`上次同步 · … · 服务 20261026.2`。那个 **服务** 后面的号就是云函数自报的版本。号不对 / 没有这一段，就说明跑的还是旧代码，重新上传一次。

> 改完权限相关的东西（比如访客账号）如果只「重新编译」小程序而不重新部署云函数，界面会变成访客版、但数据还是按老逻辑查的——表现就是**访客能看到学校账号的任务**。新版前端会自己拦掉并顶一条红字提醒，看到那条红字就是云函数没更新。

**然后必须改配置，否则一定超时失败**：

1. 云开发控制台 → 左侧「云函数」→ 点 `studyHub` → 点 **「配置」** 标签
2. **超时时间**：改成 **60 秒**（默认 3 秒，抓三个平台绝对不够）
3. **运行环境 / Node.js 版本**：如果这里有得选且能选 **18.x**，选了更好；**选不了也没关系**，云函数创建后这个字段通常锁死了，代码已经做了 Node 16.13 兼容，不用管它
4. 保存

---

## 第 8 步：改掉默认密钥（重要，先改再绑定）

1. 开发者工具左侧展开 `cloudfunctions/studyHub/lib/`，点开 `secret.js`
2. 第 8 行左右：
   ```js
   const SECRET = 'study-hub-please-change-this-secret-2026'
   ```
3. 换成你自己随便编的一串字符，**越长越好，别用这行原来的**：


   ```js
   const SECRET = 'zjdx-sw3-202515020339-x7k9m2p4'
   ```
4. 保存，然后**重新执行一次第 7 步的上传部署**

> 这串东西是用来加密你账号密码的。改晚了会怎样：之前绑的账号解不开了，得重新绑。所以一定要在第一次绑定之前改。

## 第 9 步：第一次跑起来，绑定一个平台

### 9.1 打开账号绑定页

1. 开发者工具点顶部 **「编译」**（或者按 `Ctrl + B`）
2. 模拟器里点首页那个 **「去绑定账号」** 按钮
3. 进入「账号绑定」页，选 **学习通** 那张卡片

### 9.2 学习通：用「扫码登录」（首选，最省事）

展开后默认就是 **「扫码登录」** 标签，中间会显示一个二维码。

1. **二维码要显示在电脑屏幕上**（就是开发者工具左边的模拟器里）
2. 手机打开 **「学习通」App**，右上角点 **「扫一扫」**
3. 对着电脑屏幕扫
4. 手机上会弹「确认登录」，点 **确认**
5. 小程序这边状态自动走完：`请用手机扫码` → `已扫码，请在手机上点「确认登录」` → 卡片变成「已绑定」并自动同步任务

全程十秒左右，**不用复制任何 Cookie，也不用开 F12**。

几个提醒：

- 二维码 **4 分钟**过期，过期后点下面「刷新二维码」重来一张
- 只有学习通支持扫码，希冀和 U校园 没有这个入口
- 如果提示「学习通要求人机验证（云函数出口 IP 被风控）」，说明这条路暂时走不通，退回 9.3 的 Cookie 方式

### 9.3 扫码不行？退回 Cookie 模式

在表单顶部点 **「Cookie」** 切换按钮。

Cookie 模式跳过了所有加密和风控环节，成功率同样很高，只是要手动复制一次。

### 9.4 复制 Cookie（这一步最关键，看清楚）

**推荐做法（最不容易漏字段）：**

1. 电脑浏览器打开 <https://i.chaoxing.com>，用你的账号正常登录，进到「我」的首页
2. 按 **`F12`**（笔记本可能是 `Fn + F12`）
3. 切到 **「Network」**（中文版叫「网络」）标签
4. **按 `F5` 刷新一次页面** —— 不刷新的话列表是空的，这一步最容易漏
5. 在面板顶部的 **Filter** 框里输入 `chaoxing`，列表就只剩学习通的请求
6. **右键最上面那一条** → **复制** → **复制为 cURL (bash)**
7. 得到一整条以 `curl 'https://...'` 开头的长命令

**为什么用「复制为 cURL」而不是直接复制 `Cookie:` 那一行？**

学习通有一批 cookie 是 `HttpOnly` 的，浏览器控制台里 `document.cookie` 根本读不到，手动从 Request Headers 里挑也容易漏。`复制为 cURL` 拿的是浏览器**实际发出去**的完整 Cookie 头，一个不漏。

### 9.5 粘贴并保存

1. 回到开发者工具，把整条 cURL 命令**原样**粘到 Cookie 输入框（不用自己拆，程序会自动把 `cookie` 头抽出来）
2. 点 **「保存并同步」**
3. 等一下（10～30 秒，三个平台都要抓）

**三种可能的结果：**

| 你看到                  | 说明              | 下一步              |
| -------------------- | --------------- | ---------------- |
| 提示「同步到 N 项任务」，列表出现任务 | 成功              | 继续绑定另外两个平台       |
| 弹窗「账号已保存，但抓取失败」      | Cookie 拿到了但解析失败 | 看第 14 步的日志排查     |
| 弹窗「Cookie 已失效」        | Cookie 没复制全     | 重新复制一次，确认没漏开头或结尾 |

## 第 10 步：绑定另外两个平台

这两个平台**没有扫码入口**，走 **9.3～9.5 的 Cookie 流程**：

- **U校园**：浏览器打开 <https://u.unipus.cn> 登录后再复制 Cookie
- **希冀平台（公网版）**：浏览器打开 <https://www.educoder.net> 登录后再复制 Cookie

U校园 的**网页表单密码登录走不通**（动态公钥加密，绕不过去），首选还是扫码（第 9 步那种思路，但 U校园 的扫码要开着本地代理，见下）或 Cookie。
适配器已经接了 SSO 的 JSON 登录接口（`/sso/0.1/sso/login`，收明文），账号页里也可以直接填手机号+密码试一次；反复失败就是触发了滑块，回 Cookie。

### 希冀是学校内网版（如 `http://10.67.4.14`）怎么办

> ⚠️ **别在「希冀平台（公网头歌）」那张卡里填账号密码**。那张卡走的是 `www.educoder.net`，云函数从机房发起登录。学校内网版（`10.x`）的账号不在公网头歌上，地址云函数也摸不到，所以它一定会回一句：
>
> `公网头歌 www.educoder.net 登录没拿到会话 Cookie……`
>
> 看到这句话不是账号错了，是**走错了入口**。内网版请用第 10.5 步的「校园内网直连」——页面下方那张写着「需校园网」的卡，用学号 + 希冀密码 + 图片验证码登录。

内网地址是私有 IP，**云函数永远访问不到**，所以这条不能用上面那套绑定流程，改用第 10.5 步的「校园内网直连」。

三个平台都绑完，回首页下拉刷新一下，应该能看到汇总的任务了。

## 第 10.5 步：希冀是校园内网版（`http://10.67.4.14`）

内网地址（`10.x` / `192.168.x` / `172.16~31.x`）云函数**永远连不上**，所以这个平台的抓取改成「小程序自己抓 → 结果推给云端」：

```
手机（连校园网）──wx.request──► http://10.67.4.14  抓任务、本地解析
        └──────────pushTasks──► 云数据库 tasks 集合 ──► 首页 / 统计 / 每日提醒
```

### 10.5.1 两个硬前提

1. **设备必须连校园网**（或学校 VPN）。在家里、用流量都抓不到。
2. **开发者工具「详情 → 本地设置」勾上「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**。
   因为用的是 `http://` + IP，不在合法域名白名单里。勾选后「预览」出来的开发版也生效；正式版不行（正式版必须 HTTPS 备案域名，内网 IP 无解）。

### 10.5.2 用学号和密码登录（不需要复制 Cookie）

账号页那张卡里依次填：

1. **平台地址**：默认 `http://10.67.4.14`，学校换过端口就改成实际地址
2. **学号**：`2025…` 那串
3. **希冀密码**：登录这个平台用的密码（**不是**统一认证 / 教务那个）
4. 点一下右边 **「点击取图」** 那个方框，图出来照着填进**左边那个输入框**（看不清就再点一次图片换一张；框里会显示「4/6」这样的已输入位数；**照图上大小写填**）
5. 点 **「登录」**

> 输入框是有底色和边框的那个，左对齐填；右边带图片的方框是「换一张」按钮。
> 验证码是跟会话绑的，**换图之后之前填的会作废**，得照新图重填一次。

登录成功后状态行会显示「已登录（学号 xxx）· 计算机类课程一体化平台」。

> **密码怎么上去的**：这个平台在提交前会用 CryptoJS 把密码做 AES-128-ECB 加密（key 写死在页面 JS 里），小程序的 `utils/aes.js` 做的是同一件事，所以服务器收到的是它认的那一串，不是明文。
>
> **会话怎么保持**：登录后服务器下发 `educg_session`，小程序读 `res.header['Set-Cookie']` 自己存到本机，之后每个请求手动带上——所以不用像以前那样去浏览器里复制 Cookie。

登录失败怎么对照：

| 提示 | 原因 | 怎么办 |
| --- | --- | --- |
| `验证码错误！` | 验证码填错/过期（一次性） | 重新点图片取一张再填 |
| `先取验证码` | 还没点右边那个方框取图 | 点一下带图的方框，再照图填 |
| `先填验证码` | 取了图，但左边输入框还是空的 | 把图上的字符填进左边输入框（框里会显示已填几位） |
| `学号或密码不对（验证码这关已经过了）` | 学号或密码错 | 确认用的是**希冀平台**的密码；还不行就用浏览器登一次确认账号能进 |
| `连不上 http://10.67.4.14（请求超时）` | 没连校园网 | 连上校园网 / 学校 VPN 再来 |
| `微信拦了这个地址…` | 没勾「不校验合法域名」 | 回 10.5.1 第 2 条 |

### 10.5.3 登录完会自动探测，也可以手动点

1. 登录成功后，小程序会自动跑一遍探测（十几秒），结果直接显示在卡片下方：
   - 前几行是站点首页 / 学生首页 / 登录页的 HTTP 状态；
   - 中间那行会告诉你**现在还登录着没有**；
   - 然后是**学生首页上的链接**（原样的 href）和首页里的 iframe/form；
   - 再往下是「**补充扫描（其他课程 / 其他栏目 / 翻页）**」：逐个 `tab` 栏目、逐门课程各拿到几条，哪门课打了 404、哪种切换写法有效，都写在这里；命中的页面会把前几条作业直接列出来；
   - 再往下是「摸到几门课程 / 作业列表」：这个平台的学生首页只是个**外壳页**（顶上导航 + 一个 `form /main.jsp`），而课程、作业的详情页点进去还是外壳（内容靠 JS 填，抓不到）。真正能抓的是**服务端渲染的 tab 页**，小程序会顺着 form / iframe / 页面里的 `.jsp` 往下摸（最多两层），把 `...redirect.jsp?tab=-2`（在线作业）这种**带 `assignID=` 的列表页**认出来，逐行列出作业名、截止时间、是否已提交。
   - 最后是**第一门课的实测**（如果有独立课程列表）：实际打开的那个地址、字节数、`tr/td/li` 行数、能解析出几条带截止时间的作业。
   想自己再跑一次就点 **「连通性探测」**。
2. 再点 **「直连同步」**。它会把「在线作业」列表页里的行直接变成任务（作业号是 `assignID`，跨次同步不会重复），也会打开每门课的课程页解析表格。
   - 作业号写在哪都认：`href="…assignID=802"`、`onclick="…assignID=802"`、`data-assign="802"`、单引号都行——这一行只要出现过作业号就算一条作业。
   - 作业名取这一行里**最长的那段有意义的文字**（这个平台的作业名常常是纯文本，链接反而只有「进入作业」四个字）。
   - 列表里有**截止时间就填上，没有就留空**（不编一个假的时间）——首页任务卡上会显示「无截止时间」。
   - 学期按**当前学期**记，否则首页默认只看本学期会「同步成功却看不到」。
   - **「在线作业」页一次只列一门课**（服务端按当前课程渲染）。所以同步完还会自己补一轮：换栏目（`tab=-1/-3/-4`）、换课程（先试 `?courseID=`，不灵就打开切换页让服务端记住课程，哪种写法灵就锁定复用）、翻页。成功后那条提示会写「已写入 5 项 · 3 门课」——**只写「已写入 1 项」说明平台里当前就这一条**，不是漏扫。补扫最多 15 秒，超了就先交已拿到的部分。
3. 如果提示「没摸到课程」「没敢猜」或「一门都没解析出来」，把探测结果（卡片右下角 **「复制结果」**）发出来：
   - 「没摸到课程」那段会列出**走过的每个地址和它返回的状态码**，还有首页里出现过的 `.jsp` 和正文节选；
   - 「有作业号但一行都没解析出来」那段会把**原始标签**（含属性）打出来，作业号写在哪个属性上一看就知道；
   - 「没敢猜」那段会列出它看到的行（标题 + 整行文字）。
   照这些补一次路径或字段解析即可，不用你截图整页。


### 10.5.4 它和别的平台有什么不一样

| | 学习通 / U校园 | 希冀（内网版） |
|---|---|---|
| 谁去抓 | 云函数 | 小程序（你自己） |
| 什么时候抓 | 每天 21:30 自动 + 手动 | 只有你点「直连同步」时才抓 |
| 每日提醒能覆盖吗 | 能 | 能，但提醒的是**上次直连抓到的**数据 |
| 登录方式 | 学习通喂 Cookie / 扫码；U校园扫码 | **学号 + 希冀密码 + 图片验证码**，登录一次就够 |
| Cookie / 会话存哪 | 云数据库（加密） | 只存在你手机本地，不上云 |

所以：**在学校连着校园网时，打开小程序点一下「直连同步」**，当天晚上 21:30 的提醒就有希冀的数据了。

## 第 10.6 步：学习通抓不到课程？改用本地代理（方案 A）

如果你扫码登录成功了，但一同步就报 **「读取课程失败」/「请重新登录」**，走这一节。

### 10.6.1 为什么加这一层

云函数跑在腾讯云机房，**出口是机房 IP**。超星对这类来源很敏感，经常出现「登录明明成功了，但接口就是不认」的情况——Cookie 字段一个不缺，照样返回 `请重新登录`。

解决办法很直接：**让抓取跑在你自己电脑上**。用的是你家宽带 / 校园网的出口 IP，超星没有理由拦。

```
小程序 ──HTTP──► 你电脑上的代理(127.0.0.1:7788) ──HTTPS──► 学习通
                        │
                        └── 抓到的任务 ──► 上传云端 ──► 首页 / 每日提醒照旧
```

三个附带好处：

- Cookie **只存在你电脑的内存里**，连小程序都看不到，更不会上云
- 绕开「个人小程序不能配置第三方域名」的限制 —— 本地地址不需要域名白名单
- 学习通的抓取代码一份两用，云函数和本地代理跑的是同一套

### 10.6.2 启动代理

**方式一（最简单）**：进 `study-hub\localserver\` 文件夹，**双击 `启动代理.bat`**。

**方式二（命令行）**：

```bash
cd study-hub
node localserver/server.js
```

看到这样的输出就说明起来了：

```
  学习通本地代理  v1.0.0
  ─────────────────────────────────────────────
  控制台    http://127.0.0.1:7788/
  小程序    http://127.0.0.1:7788/  （开发者工具）
  真机      http://192.168.x.x:7788/  （手机需同一 WiFi）
  ─────────────────────────────────────────────
```

> **这个黑窗口要一直开着**，关掉代理就停了。窗口里会实时打印每一步在干什么，出问题时看它最快。

如果提示 `端口 7788 被占用`，换个端口：`node localserver/server.js 7799`，小程序里的地址也要跟着改。

### 10.6.3 先在浏览器里把链路跑通（强烈建议）

先别动小程序，**用浏览器验证**最快——二维码在网页上还更大更好扫。

1. 浏览器打开 <http://127.0.0.1:7788/>
2. 点 **「生成二维码」**
3. 手机打开「学习通」App → 右上角「扫一扫」→ 对着屏幕扫
4. 手机上点 **「确认登录」**
5. 网页上状态变成 `登录成功（字段：...）`

然后点 **「抓课程列表」**（几秒钟）：

| 你看到 | 说明 | 下一步 |
|---|---|---|
| `课程数：7`，下面列着课程名 | **成功了**，登录态被超星认可 | 进 10.6.4 接小程序 |
| `课程数：0` + 一堆轨迹 | 登录态还是不认 | 把「轨迹」那段发我 |
| `登录态存活：否` | Cookie 被踢了 | 重新扫码；扫完先别关网页 |
| `失败：连不上本地服务` | 黑窗口关了 | 重新双击 bat |

> 2026-10-24 实测结果：7 门课全部解析出课程名和任课老师，作业 + 考试共 34 条，一次抓完约 2.5 秒。
> 你看到的课程数和条数会不一样，只要不是 0 就是通的。

**能抓到什么、抓不到什么：**

| 数据 | 支持吗 | 说明 |
|---|---|---|
| 课程名 / 任课老师 | ✅ | |
| 作业标题、截止时间、状态（待做 / 待批阅 / 已完成） | ✅ | 截止时间精确到分钟 |
| 考试标题、考试时间、状态（未开始 / 已结束） | ✅ | 考试没有单条链接，点进去是课程首页 |
| 章节任务点（视频、阅读任务点） | ❌ 暂不支持 | 完成状态要在课程里异步加载，逐章节请求太慢；而且它没有截止时间，优先级低于作业 |

### 10.6.4 回到小程序

1. 开发者工具右上角 **「详情」→「本地设置」**，勾上 **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**
   > 不勾的话，微信会直接拦住 `http://127.0.0.1` 这个地址
2. 重新编译小程序，进「账号绑定」页
3. 找到 **「学习通 · 本地代理」** 这张卡片，地址保持 `http://127.0.0.1:7788` 不用改
4. 点 **「检测连接」** → 应该弹出「连上了」
5. 点 **「扫码登录」** → 手机扫码 → 手机点确认
6. 点 **「抓课程列表」** 验证，通了再点 **「抓任务并上传」**

「抓任务并上传」默认只抓前 10 门课（约 20～40 秒），因为微信单次请求最长 60 秒。课多的账号可以多点几次，或者改 `localserver/server.js` 里 `actSync` 的默认 `limit`。

抓到之后会自动写进云端，**首页下拉刷新就能看到**，统计和每日提醒也都照常用。

### 10.6.5 它和其他方式的区别

| | 云函数扫码 | **本地代理** | 手动贴 Cookie |
|---|---|---|---|
| 出口 IP | 机房（容易被拦） | **你家宽带** | 机房 |
| Cookie 存哪 | 云数据库（加密） | **只在你电脑内存** | 云数据库（加密） |
| 需要 F12 吗 | 不需要 | 不需要 | **需要** |
| 电脑要开着吗 | 不用 | **要** | 不用 |
| 每天 21:30 自动抓 | 能 | 不能（只在你点的时候抓） | 能 |

所以最省心的组合是：**用本地代理把任务抓下来**，云端照旧负责展示和每日提醒。嫌每天手动点麻烦，就改成早起或睡前点一次「抓任务并上传」。

### 10.6.6 几个注意事项

- **别把 `localserver/session.json` 发给任何人**，里面存着你在学习通的登录态（明文 cookie）。这个文件已经写进 `.gitignore`，不会被提交。
- 代理监听的是 `0.0.0.0`，同 WiFi 下的设备理论上能访问。**只在自己家 / 宿舍网络用，用完关掉窗口**。想更保守就加个口令：`set CX_KEY=你的口令 && node localserver/server.js`，小程序这边暂时还不会自动带口令，需要手动改 `utils/proxy.js`。
- 只想本机访问、不给局域网开：`node localserver/server.js --localhost`（真机调试就连不上了）。

### 10.6.7 双击 `启动代理.bat` 一闪就没？

先看 `localserver/launch.log`（每次启动都会写）：

- **有日志、最后一行是「代理已在运行」** → 正常，说明已经有一个代理在跑了，脚本提示完就退出。浏览器开 <http://127.0.0.1:7788/> 能用就没事；想自己看窗口日志，先在任务管理器结束所有 `node.exe` 再双击。
- **有日志、最后一行是「没找到 node」** → Node 没进 PATH，重装时勾上 Add to PATH，或装完关掉所有命令行窗口重开。
- **根本没有 `launch.log`** → 脚本压根没被执行，通常是杀软/组策略拦截。改用同目录的 `start-proxy.cmd`（ASCII 文件名），或在文件夹地址栏敲 `cmd` 回车后执行 `start-proxy.cmd`。

## 第 10.7 步：学期（默认只看本学期）

超星里**往期的课不会消失**，秋季学期照样挂着上学期的班。那些班的未完成作业、章节任务点会一直混在首页列表里，越积越多——这就是「怎么还有上学期待办」的来源。

处理方式：抓取时按课程的**开始时间**给每条任务标学期（`content.beginDate`，没有就用 `createtime`），首页默认只显示本学期。

- 平台芯片上面会多一行学期芯片：`2026 秋 本学期 (5)` / `全部学期 (51)`，点一下就能翻往期。
- 切到「全部学期」时，往期任务会挂个灰色小标签（如 `2026 春`）。
- **往期但还没到截止的仍会显示**——上学期留的作业这周要交，正是最该提醒的。
- 学期未知的任务（希冀 / U校园）一律算本学期，不会被藏掉。

> 学期是按开学月份推的：**8 月～次年 1 月算秋季，2～7 月算春季**。学校如果 7 月就开学或者寒假特别长，改 `cloudfunctions/studyHub/lib/semester.js` 里的 `FALL_START_MONTH` 即可（记得同步改 `miniprogram/utils/semester.js`）。

**要生效必须做两件事**：云函数 `studyHub` 重新部署（新增了 `lib/semester.js`，`pushTasks` 也要接收新字段）+ 小程序重新编译，然后重跑一次「抓任务并上传」。旧数据里没有学期字段，会被当成「学期未知」照常显示。

## 第 11 步（可选）：开启每日微信提醒

**如果你不想要微信推送，这一步整段跳过**，跳过之后首页不会显示「每日提醒」那张卡片，其他功能一切正常。

### 11.1 申请订阅消息模板

1. 打开 <https://mp.weixin.qq.com>，登录你的小程序后台
2. 左侧「功能」→「订阅消息」
3. 点「我的模板」→「选用模板」，从公共模板库里选
4. 搜索关键词 **「待办」** 或 **「任务」**，选一个字段合适的。个人主体能选的类目有限，如果搜不到合适的，选「教育」类目下的提醒模板也可以
5. 选用后会看到：
   - 一串 **模板 ID**（30～40 位的字符串）
   - 一组 **字段名**，形如 `thing1`（待办事项）、`time2`（时间）、`thing3`（备注）

**把模板 ID 和字段名都记下来。**

### 11.2 把模板 ID 填到两个地方

**位置一**：`miniprogram/utils/config.js`

```js
SUBSCRIBE_TEMPLATE_ID: '你的模板ID'
```

**位置二**：`cloudfunctions/studyHub/lib/notify.js` 开头附近的 `const TEMPLATE_ID = ''`

```js
const TEMPLATE_ID = '你的模板ID'
```

### 11.3 核对字段名

打开 `lib/notify.js`，找到 `buildData` 这个函数：

```js
function buildData(ctx) {
  return {
    thing1: { value: ctx.summary },   // 待办事项
    time2: { value: ctx.deadline },   // 截止时间
    thing3: { value: ctx.detail }     // 备注
  }
}
```

**左边那三个 key（`thing1` / `time2` / `thing3`）必须换成你模板里真实的字段名。** 名字对不上微信会拒发（报 47003）。

- 如果你的模板字段是 `thing1`、`date2`、`thing3`，就把 `time2` 改成 `date2`
- 字段类型也要对：`thing` 开头的最多 20 个字，`time` 开头要日期格式，`number` 开头要数字

### 11.4 重新部署云函数

再执行一次第 7 步的上传部署。

### 11.5 在小程序里开启

1. 编译，回到首页
2. 列表最下方会出现 **「每日提醒」** 卡片，右边有个「开启」按钮
3. 点它 → 弹出微信授权框 → 点 **「允许」**
4. 卡片变成「已开启 · 还可接收 1 次」

**注意微信的规则**：这叫「一次性订阅」，你**每授权一次，只能收到一条**消息。所以想天天收到，得每次收到后回来再点一次「续订」。这是微信的限制，绕不过去。

## 第 12 步：确认定时任务生效

1. 云开发控制台 → 「云函数」→ 点 `studyHub` → **「触发器」** 标签
2. 应该能看到一个叫 `dailyDigest` 的触发器，规则 `0 30 21 * * * *`

**如果没有**：在开发者工具里右键 `studyHub` 文件夹 → 找「上传触发器」点一下。

这串规则的意思是：**每天 21:30:00** 自动跑一次（北京时间）。想改时间，编辑 `cloudfunctions/studyHub/config.json`：

```
"config": "0 30 21 * * * *"
         │ │  │
         │ │  └─ 小时（21 点）
         │ └──── 分钟（30 分）
         └────── 秒
```

比如想改成早上 7:00 就写 `0 0 7 * * * *`。改完要重新上传触发器。

**手动测试一次**：控制台里点「测试」，事件内容填 `{"Type":"Timer"}`，运行一下，看返回结果里的 `users` / `pushed` 数字。

## 常见报错对照表

| 报错信息                                              | 原因              | 怎么修                        |
| ------------------------------------------------- | --------------- | -------------------------- |
| `cloud function not found` / `FUNCTION_NOT_FOUND` | 云函数没部署          | 重新执行第 7 步                  |
| `云函数执行超时` / `timeout`                             | 默认 3 秒          | 云函数配置里超时改成 60 秒            |
| `fetch is not defined`                            | 跑的是旧版代码         | 重新上传部署云函数即可，新版已兼容 Node 16  |
| `-504002` / `145 code exit unexpected` / 日志空白     | 云函数启动即崩溃        | 代码已修（init 提前 + 惰性取数据库），重新部署；仍失败就改用「上传并部署：所有文件」 |
| `凭据解密失败，SECRET 可能已被修改`                            | 第 8 步改密钥改晚了     | 到账号页解绑重绑                   |
| `读到课程但没解析出任何任务`                                   | 平台页面结构变了        | 看第 15 步排查方法                |
| `Permission denied` / 查不到数据                       | 集合权限没改          | 五个集合都改成「仅管理端可读写」           |
| `-604101` / `invalid ip`                          | 云函数缺 openapi 权限 | `config.json` 里已有声明，重新部署一次 |
| 一直停在「正在获取二维码…」或提示获取失败                            | 云函数还是旧版，没有 `lib/qrlogin.js` | 重新部署云函数，选「上传并部署：所有文件」 |
| `学习通要求人机验证（云函数出口 IP 被风控）`                        | 机房 IP 被学习通风控     | 这条路暂时不通，改用 9.3 的 Cookie 方式 |
| `读取课程失败（Cookie 字段：…）｜课程接口说「请重新登录」…`            | 登录态字段齐全，但服务端不认  | **改用本地代理，见第 10.6 步**（这是最有效的解法） |
| 扫了码但一直停在「请用手机扫码」                                  | 二维码已过 4 分钟，或扫的是旧码 | 点「刷新二维码」重新扫               |
| `会话不属于当前用户`                                       | 换了个微信号但二维码是上一个用户的 | 退出重进账号页，重新获取二维码           |
| `连不上本地服务` / `url not in domain list`               | 代理没开，或没勾「不校验合法域名」 | 双击 `localserver/启动代理.bat`；开发者工具「详情 → 本地设置」勾上校验开关 |
| `端口 7788 被占用`                                     | 上次的窗口没关，或别的程序占了 | 关掉旧窗口，或 `node localserver/server.js 7799` 换端口 |
| `43101`                                           | 用户拒收或额度用完       | 回小程序重新点「开启」授权              |
| `47003`                                           | 订阅消息字段名对不上      | 按第 11.3 步核对字段名             |
| 保存后列表是空的                                          | 抓到了但全是已完成       | 首页点「全部」筛选看「已完成」分组          |

## 第 14 步：抓取失败怎么自己排查

这是这类工具最常见的状态，因为平台改版了。排查方法：

### 14.1 先做「网络自检」（学习通专用，一步定位）

账号卡片上，学习通那一行多了一个 **「网络自检」**。点它之后，小程序会拿你自己的 Cookie，**用你自己手机的网络**直接请求两个学习通地址，并把结果弹出来：

```
Cookie 长度 412
课程接口：HTTP 200 → {"result":0,"msg":"请重新登录",...}
课程页：HTTP 200 → HTML 58213 字节，课程链接 12 个，含 _uid
```

怎么读这份结果：

| 自检结果 | 含义 | 下一步 |
| --- | --- | --- |
| 课程接口返回 `channelList` | 你的网络完全能抓 | 问题只在云函数机房 IP，需要把抓取搬到手机上（把结果发我，我改架构） |
| 课程接口「请重新登录」，课程页有课程链接 | Cookie 没问题，是接口挑来源 | 改成解析课程页 HTML，把结果发我 |
| 两个都「请重新登录」，课程页也没有课程链接 | Cookie 本身不完整/失效 | 重新扫码或重新复制 Cookie |
| 两条都是 `❌ url not in domain list` | 微信拦了域名 | 开发者工具右上角「详情」→「本地设置」→ 勾选 **不校验合法域名** 后重试 |

弹窗右下角的 **「复制详情」** 可以把整段结果复制出来，直接发给我。

### 14.2 再看云函数日志

1. 云开发控制台 → 「云函数」→ `studyHub` → **「日志」** 标签
2. 找到最近一次调用的日志，看 `console.log` 打出来的内容
3. 扫码登录成功的那一刻会有 `[qrPoll] 扫码成功 { ready, alive, hops, keys }`：
   - `ready: true` 表示 `_uid`/`_d`/`uf` 三个字段齐了
   - `alive: true` 表示跟着页面跳转时没有被踢回登录页（即服务端认可这个登录态）
   - `hops: ['ok','ok']` 是三次探测的结果，`login` 表示被踢回登录页

### 14.3 最后才去改正则

比如查学习通，打开 `cloudfunctions/studyHub/adapters/chaoxing.js`，在 `fetchCourseWorks` 函数里，`const res = await request(...)` 后面加：

```js
console.log('HTML长度', res.text.length)
console.log(res.text.slice(0, 3000))
```

保存 → 重新部署 → 在小程序里再点一次同步 → 回来看日志。

日志里那一大段 HTML 就是平台真实返回的页面。对照着 `parseWorkHtml` 里的正则，看为什么没匹配上：

- 如果日志里 HTML 很短（几百字）且包含「登录」「验证码」字样 → Cookie 过期了，重新复制
- 如果 HTML 很长但结构跟正则对不上 → 把真实结构里的标题、状态、时间的标签改到正则里

三个平台分别改这里：

| 平台  | 文件                     | 改哪个函数                                  |
| --- | ---------------------- | -------------------------------------- |
| 学习通 | `adapters/chaoxing.js` | `parseWorkHtml` / `parseTaskPointHtml` |
| 希冀  | `adapters/educoder.js` | `toTask` 里的 `pick(raw, [...])` 字段名     |
| U校园 | `adapters/unipus.js`   | 顶部接口路径常量 + `sync()` 的解析段（uai 真实接口）     |
